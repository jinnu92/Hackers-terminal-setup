Make it smaller or switch it off with hts config welcome compact or hts config welcome off; hide addresses with hts config welcome_ip hide. Changes apply in the next tab.

🖥️ GPU-Accelerated Terminal Emulator Matrix

Four GPU-accelerated terminal emulators, each configured with the Catppuccin Mocha colours. What gets installed depends on the platform; a terminal's config is written only if that terminal is present.

Ghostty (Zig + Metal/GTK4) WezTerm (Rust + Lua Scripting) Kitty (OpenGL + GPU Shaders) Alacritty (Rust Minimalist)
👻 Ghostty macOS / Arch

Created by Mitchell Hashimoto. Written in Zig. Native macOS tabs and windows. Installed on macOS (cask) and Arch (pacman); skipped on apt and dnf, which have no official package.

⚡ WezTerm (Cross-Platform Lua Multiplexer) Lua Engine

Terminal emulator and multiplexer written in Rust, configured in Lua. On apt it adds the upstream apt repository; on dnf the upstream nightly COPR.

# ~/.config/wezterm/wezterm.lua 
local wezterm = require 'wezterm'
local config = wezterm.config_builder()
config.color_scheme = 'Catppuccin Mocha'
config.font = wezterm.font('JetBrains Mono')
config.font_size = 13.5
config.enable_tab_bar = true
config.window_background_opacity = 0.94
config.macos_window_background_blur = 20
return config
# Install matrix (--terminals) 
           macOS  apt          dnf     pacman  zypper
Ghostty    yes    skipped      skipped yes     no
WezTerm    yes    upstream apt COPR    yes     no
Kitty      yes    yes          yes     yes     yes

No GUI terminals are installed on WSL or on headless Linux. Alacritty on apt needs Debian 13+ or Ubuntu 24.04+.

# Kitty and Alacritty

Kitty (~/.config/kitty/kitty.conf) and Alacritty (~/.config/alacritty/alacritty.toml) get the same Catppuccin Mocha colours, JetBrains Mono Nerd Font, and window padding and opacity settings.

📦 Modular Architecture (lib/ Breakdown)

Each domain lives in its own module under lib/. bundle.sh joins the modules into ter.sh, the single file that is piped from curl.

Directory Structure: 
Hackers-terminal-setup/
├── ter.sh                # Generated single file (built by bundle.sh)
├── bundle.sh             # Joins lib/*.sh into ter.sh
├── terminal_preview.html # Interactive visual showcase and profile builder
├── lib/
│   ├── common.sh         # Colours, logging, OS detection, results table
│   ├── versions.sh       # Pinned versions and SHA-256 digests
│   ├── pkg_mgr.sh        # brew, apt, dnf, pacman, zypper wrapper
│   ├── helpers.sh        # Go toolchain, pipx and go install helpers
│   ├── preflight.sh      # Homebrew, Oh My Zsh, disk space checks
│   ├── fonts.sh          # Modern Nerd Fonts multi-distro installer
│   ├── dev.sh            # Node.js LTS, Claude Code, VS Code CLI
│   ├── terminals.sh      # Ghostty, WezTerm, Kitty, Alacritty + configs
│   ├── shell_tools.sh    # Atuin, direnv, uv, btop, yazi, delta, Starship
│   ├── ad_pivoting.sh    # Ligolo-ng, Chisel, NetExec, BloodHound, Certipy
│   ├── web_api.sh        # Schemathesis, Kiterunner, Caido, Arjun, FFUF
│   ├── cloud_devsec.sh   # Trivy, Syft, Grype, Checkov, kubescape, kube-bench, osv-scanner
│   ├── mobile_re.sh      # jadx, Apktool, frida-tools, objection
│   ├── pentest.sh        # Core offensive security auditing suite
│   ├── bugbounty.sh      # Web recon, discovery & nuclei automation
│   ├── cloud.sh          # Cloud provider CLIs and cloud security tools
│   ├── ai_mcp.sh         # MCP suite, sec-mcp, AI/LLM security tools
│   ├── workflow.sh       # lazygit, jq, yq, gh, pandoc, xh, yazi
│   ├── dashboard.sh      # Fastfetch & Tactical Security Welcome Cockpit
│   ├── doctor.sh         # Diagnostic audit (text and JSON)
│   ├── configs.sh        # Dotfile generators (.zshrc, .tmux.conf, configs)
│   ├── lifecycle.sh      # --status, --restore, --uninstall, --update
│   └── menu.sh           # Menu, component table, argument parsing
Key Architectural Principles:
  • ✓ Generated single file
    ter.sh contains every module. Edit lib/*.sh, then run ./bundle.sh. Run from a clone, it sources lib/; piped from curl, it uses the bundled copy only.
  • ✓ Clean Domain Isolation
    Each domain (Active Directory, Web APIs, Containers, Mobile, AI) has its own module and doctor checks.
  • ✓ Pinned, verified downloads
    Direct downloads are pinned in lib/versions.sh and checked against SHA-256 digests. Package-manager and pipx packages are not pinned.

🧰 Preview, Inspect and Undo

The installer can show what it would do, report what it did, and put your dotfiles back. Every dotfile it rewrites is copied to ~/.local/state/hts/backups/ first, and each run writes a log and exits non-zero if any step failed. Run the lifecycle commands on their own, not combined with component flags. The output below is simulated.

--dry-run --status --restore --uninstall --purge-tools --update hts config
ter.sh lifecycle
simulated output

Core terminal (--core) would install: fzf bat eza zoxide git-delta tmux fd ripgrep tldr; Powerlevel10k ... Run a lifecycle command:
# What each command does
  • --dry-run lists what would be installed and which files written; changes nothing.
  • --status shows installed components, tracked tools and files, backup runs and the log path.
  • --restore [TS] puts back the earliest backup of each file (or one run). It backs up the current file first.
  • --uninstall restores backups and removes files the tool created. It asks first.
  • --uninstall --purge-tools also removes tools recorded in the manifest.
  • --update checks for a newer release and upgrades recorded tools (Go tools move to @latest).
# Not undone automatically
  • Login shell change: chsh -s <previous shell>
  • Homebrew itself and Oh My Zsh
  • Package repositories and signing keys that were added (apt sources, taps, COPR)
  • npm prefix: npm config delete prefix
  • Tools, unless you pass --purge-tools

Your own additions in ~/.zshrc.local are never touched by the installer.
